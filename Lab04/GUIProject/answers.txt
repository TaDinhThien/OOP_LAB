Lab 04 - GUI Programming with Swing

1. Compare AWT and Swing

- Top-level container:
  - AWT: uses Frame
  - Swing: uses JFrame (more flexible, supports lightweight components)

- Component naming:
  - AWT: Label, TextField, Button
  - Swing: JLabel, JTextField, JButton

- Event handling:
  - Both use ActionListener, but Swing supports more event types and flexibility.

- Look and feel:
  - AWT: native UI of the OS
  - Swing: consistent across platforms

2. Compare layout managers

- BorderLayout: used to organize components in five areas (NORTH, SOUTH, EAST, WEST, CENTER).
- GridLayout: divides container into equal-sized cells (used for Media grid).
- BoxLayout: arranges components in a single row/column (used for headers and item panels).
- FlowLayout: places components in a row, used for small button groups.

3. Summary of GUI Implementation

- SwingAccumulator: a simple Swing GUI app that accumulates integers input by the user.
- NumberGrid: allows input of digits using buttons, with delete/reset options.
- StoreManagerScreen: the main screen for the Store Manager role in the AIMS project.
  - Displays all Media items in a grid layout.
  - Includes menu bar to switch screens (Add Book, Add CD, Add DVD).
  - Allows playing media with "Play" button if the item is Playable.
- AddItemToStoreScreen: abstract base GUI class for adding new items.
- AddBookToStoreScreen: screen to input title, category, cost for a book.
- AddCompactDiscToStoreScreen: adds artist input field.
- AddDigitalVideoDiscToStoreScreen: adds director and length input fields.

4. Bonus Notes

- All GUI components are placed under package: hust.soict.hedspi.aims.screen.manager
- Java version used: Java 21 (with enhanced switch, pattern matching, etc.)
- Applied OOP concepts: inheritance, abstraction, polymorphism, encapsulation.
- All media classes (Book, CD, DVD) inherit from Media and override playGUI() when applicable.
